# Upper bounds are deliberate. This app deploys to Streamlit Community Cloud, which re-resolves
# these on every restart - so a bare `>=` means an upstream release can break production with no
# change on our side and no warning. Not hypothetical here: the deployed app was already running
# on a stack nobody chose (Python 3.14 / pandas 3.0 / Streamlit 1.60) purely because those were
# newest at deploy time, while the code still used `use_container_width`, whose documented removal
# date had already passed.
#
# Lower bounds are real requirements, not guesses:
#   streamlit 1.49+  - width="stretch" (the replacement for the deprecated use_container_width)
#   pandas 2.0+      - the tz-aware DatetimeIndex behaviour every research script assumes
#
# Raise these deliberately, then re-run the webapp tests and one real backtest before deploying.
streamlit>=1.49,<2.0
pandas>=2.0,<3.1
numpy>=1.24,<3.0
dukascopy-python>=4.0,<5.0
plotly>=5.20,<7.0
tqdm>=4.65,<5.0
requests>=2.28,<3.0
